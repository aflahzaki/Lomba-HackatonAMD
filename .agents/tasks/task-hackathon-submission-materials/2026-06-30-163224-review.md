# Hackathon submission documentation for LangkahKampus

Five markdown documents form the submission package for AMD Hackathon ACT II: a step-by-step submission guide, a timed video script, a 10-slide presentation outline, a technical AMD-usage document, and README additions linking everything together. File path references resolve to real files, timing adds up to ~4:30, and the AMD narrative is threaded throughout.

**Watch for:** The claim that Fireworks AI runs on AMD hardware is stated as fact across all documents but is unverifiable from the codebase (likely). The submission guide points users at `feat/ai-backend-integration` as the primary branch rather than `main`, which could confuse judges expecting a clean default branch (confirmed). One image referenced in the slide outline (`references_images/xai_framework_comparison.png`) exists but is used on the "Architecture" slide where its relevance is unclear (possible).

## High-level view

The submission guide names `feat/ai-backend-integration` in its checklist as the branch that should be "clean and buildable" — judges landing on `main` will find this confusing. Either merge before submission or explain the branch strategy in the guide.

The video script's AMD integration segment (45 seconds) scripts ~150 words of narration plus four code highlights and two chart displays. At natural speaking pace that's 70+ seconds of speech alone — the segment will either feel rushed or push the total past 4:30.

The AMD usage document accurately reflects the training script's ROCm detection logic and XGBoost GPU parameters. Its weak point is the repeated assertion that Fireworks AI infrastructure uses AMD GPUs — plausible but not verifiable from the codebase and presented without citation.

The README places "AMD Platform Integration" before Quick Start (prominent for judges) and "Submission" after directory structure. Both sections link correctly to the new docs.

## Branch reference in submission guide

The pre-submit checklist in `SUBMISSION_GUIDE.md` states:

> Branch utama (`feat/ai-backend-integration`) clean and buildable

Judges will clone the repo and see `main` as the default branch. If the submission branch is intentionally a feature branch, the guide should explain this or the team should merge to `main` before submitting. As written, a checklist reviewer might believe the feature branch *is* the primary branch, which creates confusion about what to review.

## Fireworks AI and AMD hardware attribution

Across `docs/AMD_USAGE.md`, `docs/VIDEO_SCRIPT.md`, the README, and `SUBMISSION_GUIDE.md`, the documents state that Fireworks AI "runs on AMD hardware" or "runs model inference on AMD hardware." The actual integration code (`ai_backend/app/services/advisor.py`) calls `https://api.fireworks.ai/inference/v1/chat/completions` — a third-party API endpoint. Whether that endpoint runs on AMD GPUs is a claim about Fireworks AI's infrastructure, not something the project controls or can verify.

This matters because one judging criterion is "Use of AMD Platforms." If judges probe this claim, the team should have a citation ready (Fireworks AI's hardware partnerships page, a blog post, or similar). The documents currently present it as established fact without attribution.

## Video script timing feasibility

The video script assigns time budgets per segment:

```
Intro:        0:00 – 0:30 (30s)
Problem:      0:30 – 1:00 (30s)
Prediction:   1:00 – 2:00 (60s)
AI Advisor:   2:00 – 2:45 (45s)
AMD:          2:45 – 3:30 (45s)
Architecture: 3:30 – 4:00 (30s)
Closing:      4:00 – 4:30 (30s)
```

Segment 5 (AMD Integration) scripts approximately 150 words of narration. At natural English speaking pace (~130 words per minute), that is 70 seconds of speech — 25 seconds over budget. The segment also requires scrolling through code, zooming on two parameters, and displaying two evaluation charts for 3-4 seconds each.

The simplest fix: cut the narration paragraph about "XGBoost's device='cuda' parameter works seamlessly..." (redundant with the previous paragraph that already establishes HIP compatibility) and consolidate the two chart displays into a single split-screen moment.

## Slide image placement

Slide 5 (Technical Architecture) lists `references_images/xai_framework_comparison.png` as a supporting image. That image is a comparison of explainable AI frameworks — a machine learning concept — not a system architecture diagram. It fits better on Slide 7 (ML Model Performance), which discusses model selection. Alternatively, drop it since Slide 7 is already image-heavy with four charts.
