# Production-readiness middleware and advanced ML endpoints for LangkahKampus

The AI backend gains a middleware stack (rate limiting, security headers, structured logging, global exception handling), an in-memory metrics collector, and three new endpoints: SHAP-based explainability, batch prediction, and what-if analysis. Docker compose picks up health checks and restart policies; a GitHub Actions CI pipeline builds and tests on push.

Watch for: `metrics.record_request()` is defined but never called, so `total_requests`, `avg_response_time_ms`, and `endpoint_stats` are always zero (confirmed). The CSP header `default-src 'self'` will break Swagger UI and any cross-origin API consumers (confirmed). The MetricsCollector is a plain Python object with no concurrency protection, meaning counters can drift under concurrent requests in async workers (likely).

## High-level view

The logging middleware duplicates the global exception handler's job — both catch unhandled exceptions and return a JSON 500. Only one fires in practice (logging middleware wins because it's higher in the Starlette stack), making the registered `global_exception_handler` dead code.

The MetricsCollector tracks predictions, explanations, batch requests, and what-if calls via explicit method calls in each endpoint. But the generic per-request tracking (`record_request`, `total_requests`, `avg_response_time_ms`, `endpoint_stats`) is never wired up — no middleware or hook invokes it — so the `/api/metrics` response reports zeros for those fields permanently.

Rate limiting uses slowapi with `get_remote_address` as the key function. Behind the PHP container (which proxies all user requests), this resolves to the proxy IP rather than the real client, effectively making every user share a single rate-limit bucket.

The SHAP explainability service falls back gracefully to pseudo-SHAP values when TreeExplainer fails. However, `explain_prediction` reconstructs features independently of the predictor's internal logic; if the predictor's feature construction ever diverges, SHAP values will be computed on different inputs than the actual prediction.

Batch prediction iterates students sequentially in an async endpoint with no concurrency or chunking. For 50 students with the current small model this is tolerable (~500ms), but the event loop is blocked for the full duration.

The CSP `default-src 'self'` header applied to every response will block the interactive Swagger UI docs (which load external JS/CSS). For the production path (server-side PHP curl), CSP is irrelevant, but it breaks the development experience via `/docs`.

5. **MetricsCollector not thread-safe** — Plain int increments and dict mutations on a shared global can race under concurrent async workers. Use `asyncio.Lock` or atomic counters if accuracy matters; if approximate is acceptable, document that.
6. **Feature construction divergence risk in explainer** — `explain_prediction` rebuilds the feature vector independently of `predictor.predict`. A shared feature-construction function would eliminate drift risk.
7. **Batch endpoint blocks the event loop** — 50 sequential predictions hold the async loop. Consider `asyncio.to_thread` or chunked processing for large batches.

## Middleware stack ordering and exception handling overlap

```python
app.add_middleware(CORSMiddleware, ...)
app.add_middleware(StructuredLoggingMiddleware)
app.add_middleware(SecurityHeadersMiddleware)
```

Starlette processes these in LIFO order, so the effective request flow is: SecurityHeaders -> Logging -> CORS -> route handler. `StructuredLoggingMiddleware.dispatch` wraps `call_next` in a try/except that catches *all* exceptions and returns a JSONResponse directly. Separately, `app.add_exception_handler(Exception, global_exception_handler)` registers the same behavior. Since the middleware sits above the exception handler layer in Starlette's stack, the middleware's catch fires first and the registered handler is unreachable. The `global_exception_handler` in `middleware/error_handler.py` is dead code.

The middleware's catch or the exception handler should be removed — having both creates confusion about which path runs.

## Metrics collector: partial wiring

`MetricsCollector` exposes `record_request(path, response_time_ms)` which populates `total_requests`, `total_response_time_ms`, and `endpoint_stats`. No code in the application calls this method. The logging middleware computes `response_time_ms` but doesn't pass it to the metrics collector. The fields are returned from `GET /api/metrics` as zeros.

Fix: add `metrics.record_request(request.url.path, response_time_ms)` in the logging middleware's dispatch, after computing the response time.

## CSP header scope

```python
response.headers["Content-Security-Policy"] = "default-src 'self'"
```

Applied unconditionally to every response. For the `/docs` and `/redoc` OpenAPI pages, this blocks the Swagger UI JavaScript bundle (loaded from CDN by default in FastAPI) and the ReDoc script. Swagger UI renders a blank page with CSP violations in the console.

Options: exclude documentation paths from the CSP header, add CDN origins to the allow list, or serve Swagger assets locally.

## Rate limiting under reverse proxy

```python
limiter = Limiter(key_func=get_remote_address)
```

`get_remote_address` extracts `request.client.host`. In the docker-compose topology, the PHP container makes HTTP requests to `ai-backend:8000`. From the AI backend's perspective, every request comes from the PHP container's IP. All users share one rate-limit bucket.

Configure slowapi to use `X-Forwarded-For` or `X-Real-IP`, and ensure the PHP proxy sets those headers.

## SHAP explainability: feature vector alignment

`explain_prediction` manually constructs the feature array:

```python
features = np.array([[avg_score, ranking_percentile, accred_score, competition_ratio, applicant_trend, daya_tampung]])
```

It then calls `predictor.predict(...)` separately. The predictor's internal `predict` method also constructs a feature array using the same inputs. If the predictor's feature engineering changes (e.g., adding a feature, changing normalization), the explainer's feature vector will silently diverge from what the model actually sees, and SHAP values will be computed on the wrong input.

A shared `_build_features(avg_score, ranking_percentile, accreditation, program)` function in the predictor would eliminate this risk.

## Batch prediction: sequential processing

The batch endpoint iterates students in a plain `for` loop inside an `async def`. Each iteration calls `predictor.predict()` which is synchronous (sklearn/joblib). For 50 students, the event loop is blocked for the entire batch duration (~500ms with the current model). If the model grows or latency requirements tighten, this becomes a problem. `asyncio.to_thread` wrapping the computation or chunked processing with `await asyncio.sleep(0)` between chunks would yield back to the loop.

## Test coverage gaps

Not tested: the CSP header's interaction with the docs endpoint, the behavior of rate limiting under concurrent requests (only the handler's response format is tested, not actual limiting), or the batch endpoint's behavior when one student in the middle has invalid data while others are valid (currently the entire batch fails on the first bad student — a partial-success model might be more useful for the "guru BK" use case).
